# Project collaboration conventions

- At the end of every work cycle, write a Markdown accomplishment report in
  `reports/`. Use a unique, descriptive filename with the user's local date.
- Describe what was accomplished, files changed, validation actually performed,
  and any remaining work or limitations. Link the report in the final response.
- Whenever files change, include a suggested Git commit message in both the
  report and final response. Providing a message does not require making a commit.
- Keep implementation within the milestone authorized by the user. Milestone 2
  is complete; do not begin Milestone 3 without authorization.
